# Virtual Card Compromise & Fraud Incident Protocol
> **Document ID:** `DOC-SUP-014` | **Version:** 1.4 | **Effective Date:** 2025-11-20 | **Status:** ACTIVE
## Section 1: Compromise Detection

Virtual card anomalies are identified through real-time fraud velocity triggers or direct customer reporting via the mobile security center.

## Section 4: Virtual Card Compromise Protocol

The agent must immediately freeze the virtual card via the admin console, invalidate active session tokens, file an incident report with fraud operations, and issue a replacement card with a new card number. The customer must be notified via SMS and email with an incident reference code.

## Section 5: Transaction Disputes on Stolen Cards

Any unauthorized charges posted within 24 hours preceding the freeze request must be escalated to the dispute reconciliation unit under code DISP-FRD-401.
